# Review of TASK-112 / 116 / 115 (Antigravity commits on feat/task-113-honesty-pass lineage)
npm still at 0.3.0 (not published). npm test passes, but the tests miss the defects below.

## Blockers (security / §7)
1. Allowlist + permission mode live in the PAGE's localStorage (`eo_safety_allowlist`). Any site can whitelist itself: probe → `allowedVia: "allowlist"` for "Delete account". Move to chrome.storage (extension) / closure state; never trust page storage.
2. `window.SafetyGate` exported globally (main.tsx): page script can `setConfirmHandler(()=>true)`, `clearHooks()`, `allowOrigin()`.
3. No confirm handler is ever registered (grep: 0 calls). Irreversible actions are silently blocked; ask_all with no handler PROCEEDS (fail-open). The confirm card from the spec does not exist.
4. Gate bypasses: plan_only/ask_all check tool names only → `browse {action:"click"}`, `fill`, `input`, `download`, `hover`, `play/autopilot` pass; `clickCoordinates` (normX/normY) never classified; `type` with `pressEnter` submits forms without a "submit" check.
5. Classifier holes (probe): "Next: Place order", "Close account", "Confirm deletion", "Show more and buy now" → SAFE (SAFE_CONTEXT checked before FINANCIAL; "close/next/show more" whitelists).
6. Voice: Tier 1 Web Speech API in Chrome sends audio to Google servers, yet code + TASK-115.md say "private, on-device", "zero cloud egress". Violates TASK-115 "do not send audio off-device" and §7.
7. Voice "benchmark": "Raw ASR WER 231.7% → 58.3%" is computed on 6 hand-typed strings, no ASR involved. Must not be reported as ASR WER.
8. reasoningManager header claims "verified against DeepSeek's official API specifications (2026)" with no citation.

## Functional bugs
- Whisper path never captures audio (no `audioChunks.push`, no recorder/worklet, no 16 kHz resample) → always transcribes empty buffer.
- Web Speech finish replaces `onresult`; results finalised before stop are lost unless a new event fires.
- TodoManager.createPlan is never called at runtime and `onPlanApprovalRequired` is never passed → plan UI + approval gate are dead code; plan never cleared, so a stale plan would leak into later prompts.
- Click is gated twice (harness + ActionDispatcher.click), once per `repeatCount`; the dispatcher's `false` return is ignored, so a blocked click reports "Successfully clicked".
- Observation budget: `read(mem://…)` of a >1200-char observation is truncated again into a new mem key → full text can never be read.
- `update_task` defaults: no args → marks task 1 "completed".
- Self-correction regex: "4, no 5pm" (spec example) unchanged; "Thanks, I mean it" → "It."; "kind of" stripped from "What kind of car".
- TextInjector clipboard fallback overwrites the user's clipboard and returns success:true (verified:true when no field).
- Gemma 4 thought delimiters `<|channel>thought…<channel|>` not handled by ReasoningManager.

## SOLID / readability
- SRP: SafetyGate = classifier + mode store + allowlist store + hook registry + confirm flow + prompt wrapper (575 lines, all static). Split: ActionClassifier (pure), PermissionPolicy, AllowlistStore (injected storage), HookPipeline.
- DIP/testability: static singletons + direct localStorage; inject a storage port and a confirm port.
- OCP: classification = cascade of 4 copy-pasted blocks; use a table of {category, regex} rules.
- Hooks live in SafetyGate but run from AgentHarness; gate is also called inline in 3 primitives → one enforcement point (pre-hook with resolved element) instead of three.
- `tool as any`, `Record<string, any>`; import style mixes `.ts` extensions (voice files) with extensionless elsewhere.
- Comments overclaim ("Tri-Tier", "SOTA", "guarantees user speech is never lost").
